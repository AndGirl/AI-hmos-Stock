FR-06 · 个股详情 / 子需求 06.1

一个内容组件，三种壳

详情的界面只实现一次（DetailContent）。「从哪里出现、能不能返回、动作栏长什么样」由壳决定。下面三组界面用的是同一套内容组件，差别只在壳与紧凑参数。

01

壳与内容的从属关系

三种壳的差异只在「宿主」与「呈现」；内容组件零分叉。

A

DetailPage

宿主
列表行、卡片、搜索结果、深链
提供
路由与返回栈、沉浸式与系统栏、安全区、常驻动作栏
传参
mode=page，compact 由宽度决定
B

DetailPane

宿主
FR-02 列表右栏、FR-05 搜索右预览
提供
宽度约束 404、选中联动、右上「⋯」菜单
传参
mode=pane，compact=true
C

DetailWindow

宿主
FR-08 分屏、全景多窗
提供
独立窗口与标题栏、独立 code、独立订阅
传参
mode=window，compact=true

DetailContent · 一份实现

props：code mode compact；events：onAction onLoaded。 常量：报价头、指标面板、资讯条、图表、盘口、内容 Tab。
禁令：不自带路由、不渲染全局 banner、不起重连定时器、不假设自己是全屏。

03

职责边界

这张表就是 06.1 的全部约束；表外的事都不属于 06.1。

事项壳内容
路由、返回栈、返回手势负责禁止
沉浸式、系统栏、安全区负责禁止
全局 banner负责（全局单例）禁止
宽度与 compact 判定计算后传参按参数渲染
动作栏形态（常驻栏 / ⋯）决定只发 onAction
行情订阅不订阅按 code 订阅，销毁退订
重连定时器禁止禁止（单一调度器）
缓存不持有同 code 复用，换 code 不复用
04

一次进入的生命周期

从左到右：谁在什么时候做什么。

列表 / 搜索点行或选中把 code 交给壳，不直接建界面
壳建页 / 建栏 / 建窗push 或挂载；路由只在这一处发生
内容挂载并订阅按 code 拉首屏，骨架 ≤300ms
壳传 compact按可用宽度决定紧凑版或标准版
内容换 code周期回分时、滚动回顶、缩放重置
壳返回 / 关窗销毁壳；内容随之退订并释放图表
05

五种典型错法

出现任意一种，就说明壳 / 内容没有分开。

✕内容里写路由跳转

在右栏点一下，整个列表页被推走，回来时列表状态全丢。

例 2 直接破功

✕内容里渲染全局 banner

分屏两窗各画一条「行情连接中断」，违反 CC-7.3 单例约定。

AC-62 不通过

✕内容假设自己全屏

按 100% 高设计，塞进 404 宽的右栏后图表被压成一条线或溢出。

例 2 布局溢出

✕每个实例自建刷新定时器

双窗双倍请求，行情通道压力翻倍，还出现两窗价格短暂不一致。

性能与一致性双输

✕把行情缓存放在壳里

同一只股票在右栏与全屏页显示不同价格，用户截图即成缺陷。

例 6 数据分叉
06

举例后仍需拍板的三条

这三条不是错法，而是 06.1 目前没写死的行为，需要确认后补进规格。

06.1-a

换 code 时局部状态是否重置

周期、缩放、指标展开在切换股票后是否回到默认？

建议：跟随 code 重置（回分时 / 回默认 / 收起）；只有同一 code 跨壳才保持。
06.1-b

深链进入后返回去哪

没有来源列表时，返回键应该回首页还是退出应用？

建议：回落自选首页，不直接退出应用。
06.1-c

右栏换股票时滚动位置

右栏停在上只股票的盘口中部时，换一只股票从哪开始？

建议：回到顶部，避免停在半截内容上。
