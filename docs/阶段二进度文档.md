## 10. 高频坑（M6 起累计）

1. **`ForEach` key 不变会复用旧组件**：搜索段用 `section.kind` 做 key，结果替换后仍显示上一帧（搜 `600519` 显示 67 条「6」的结果）。修法：VM 拍平 `items` + key 带版本号（`SearchSectionVM` / `SearchItemVM`）。
2. **异常态分支必须优先于旧结果**：`SearchBody` 先判 `items.length > 0` 会让 error/429 被旧结果挡住；空/错/限流分支要放在结果分支之前。
3. **LRU 缓存会绕过 debug 故障注入**：同 term 命中缓存直接返回成功；注入前调用 `SearchQuery.clearCache()`。
4. **数字逐字符输入会触发多次查询**：`ui text "600519"` 会依次产生 `6`/`60`/… 的 onChange；首字符即查 + `seq` 丢弃旧响应可保证最终一致，但埋点会多一次 `search_query`。
5. **行点击挂在 `Row` 上，UiTest 点文本不一定命中**：进入详情改为「行内价格区坐标点击」（`getBounds()` + `driver.click(x,y)`）。
6. **`NavDestination` 标题栏不暴露为 Text 节点**：UiTest 断言详情页要用内容（如「今开」），不要用「个股详情」。
7. **长按 `TextInput` 会弹系统文本选择菜单**：搜索调试入口放在搜索条左侧图标区（`Column` 的 gesture），不要指望长按输入框。
8. **hvigor daemon 环境冲突**：`devecocli build` 报 `spawn java ENOENT` / 打包失败，多为此前用另一套 node/hvigor 起过 daemon；先 `hvigorw --stop-daemon` 再 `devecocli build`。
9. **hdc 多目标**：`onDeviceTest` 内部裸调 `hdc`，多设备会报 `need connect-key`；测试期间只保留 1 个目标（停模拟器/拔真机）。
10. **UiTest 前置**：设备必须解锁亮屏；首次 `hdc shell param set persist.ace.testmode.enabled 1`；否则报 `unlock screen failed` / 无 testmode。
11. **`onDeviceTest` 会重装应用并清掉自选数据**：本次跑完 8 例后自选从手工构造的 5 只回到 45 只种子（`watchlist_v1`/迁移标记被清）。需要保留设备上的自选状态时，先跑测试再手工验证；反之可把「清数据后 45 只」当作确定初态。
12. **截图坐标要按真机像素取**：`ui screenshot` 预览是缩放图，点按坐标必须用 `ui layout` 的节点 bounds（本次按预览图估算连点空处，误触发了搜索页与调试菜单）。
13. **自选调试「清空自选（空态）」现在是真删数据**：会清 `watchlist_v1` 的 items 并立即落盘，重启仍空；验证完用「重置」恢复 45 只种子（也会落盘），不要拿它当"看一眼空态"的临时开关。
11. **preferences 必须注入 context**：HAR 内不能自己拿 AbilityContext；由 `EntryAbility` 注入。
12. **`.hvigor` 目录权限**：本工作区曾因 Windows ACL 缺 `WRITE_OWNER` 导致 `mkdir .hvigor/.build-lock` EPERM；用权限诊断脚本修复后正常（报告在 `acl-report/`）。
13. **M7：`ui layout` 输出是字符串数组，不是 MatchInfo**：`$lines = devecocli ui layout ...` 后要 `$_ -match`，写成 `$l.Line` 会永远为 null、脚本静默不点（本次因此误触发多轮）。解析坐标统一用 `[regex]::Match($line, '\[(\d+),(\d+),(\d+),(\d+)\]')`。
14. **M7：竖排版面坐标会随键盘/浮层位置变化**：同一按钮在键盘弹出前后 y 差 500~900px；每次点击前重新 `ui layout` 取 bounds，不要复用上一轮坐标（删除分组时曾点到遮罩把浮层关掉）。
15. **M7：分组 Tab 压宽度会截断名称**：把每个 Tab 压到 `barWidth/5` 后「融资融券」显示成「融…」；改为自然宽度 + 横滑。
16. **M7：`@Monitor` 不能监听普通字段变化**：添加页勾选态必须落在 `@Trace`（`SearchRowVM.picked` / `AddWatchlistVM.pickedCount`）；结果集重建后要用 `SearchVM.resultVersion` 触发 `reapplyPicks()` 把勾选刷回新行对象。
17. **M7：键盘避让两套行为**：添加页是 push 的 NavDestination，系统不整体上移，需自持 `keyboardHeightChange` 给底部按钮让位；自选页（TabShell 内）系统会整体上移，再叠加 padding 会「顶两次」（分组管理浮层曾整体飞出屏幕）。
18. **M7：`onDeviceTest` 要求只有 1 个 hdc 目标**：本次模拟器（127.0.0.1:5555）+ 真机同时在列，报 `need connect-key`；先停模拟器进程再跑。
19. **M7：`devecocli run` 重装不清应用数据**：手工验证时自建分组/「填满至 50」会跨重装保留；要回到确定初态用调试「重置」，不要假设重装即 45 只。
20. **M7：多个 UiTest `describe` 不能各自 `Driver.create()`**：M6/M7 两套同跑（不带 `scope`）会报 `uitest-api dose not allow calling concurrently`；统一从 `test/TestDriver.ets` 的 `sharedDriver()` 取单例。
21. **M8：`Stack` 里 `height('100%')` 会把自适应高度的卡片撑成一屏**：卡片闪烁层若用百分比高度，`Grid` 第一行就吃掉整个视口（只显示 2 张卡，后面空白）。改为 `onAreaChange` 实测卡身高度、闪烁层按该高度铺满（见 §9-34）。
22. **M8：`Grid.onScrollIndex` 只回调 2 个参数**（`(first, last)`）：照文档写 3 个参数会编译报 `not assignable to (first: number, last: number) => void`。
23. **M8：`devecocli ui click` 用位置参数**：`ui click 1182 552 --device <sn>` 或 `ui click --id <节点 id>`（自动取中心）；写 `--x/--y` 会被忽略、静默不点。同理 `ui layout` 输出是**字符串数组**，解析坐标要 `[regex]::Match($line, '\[(\d+),(\d+),(\d+),(\d+)\]')`，不要当对象取属性。
24. **M8：验证「排序生效」要在点完列头后立刻取证**：排序是快照序（点列头时排一次），之后行情继续跳动不会重排；隔几分钟再截图，数值看起来已不单调，容易被误判成「排序失效」。
25. **M8：hdc 掉线时 `onDeviceTest` 报 `unlock screen failed in developer mode`**：先确认 `hdc list targets` 非空、设备亮屏解锁（`power-shell wakeup` + 上滑），再跑测试；采集中途掉线会丢 `hilog` 缓冲（本次 50 卡滚动采样即因此待补）。
26. **M12：`/setPreferredOrientation` 只在主窗上调用**：`OrientationHost` 由 `EntryAbility.onWindowStageCreate` 注入 `getMainWindowSync()`；详情页用 `NavDestination.onShown/onHidden`（不是 `aboutToAppear`）才能在 Pk/交易弹层覆盖时恢复，避免其它页横屏。
27. **M12：Resource 不能做算术**：`AppDim.gap16` 是 `Resource`，写 `landscapeLeftWidth(...) - AppDim.gap16 * 2` 会编译失败；横屏内边距直接用数字（32/24）。
28. **M12：横屏读数条不要放在图表 Stack 里**：初版把读数条放图表底部，无光标时会显示孤立的「量」标签且不算「底部工具条」；正确做法是 `ChartArea` 上抛 `onReadoutChanged`，`DetailContent` 在动作栏上方渲染 22vp 通栏 `ReadoutBar`。
29. **M12：折叠/展开比 `emulator rotate` 更可靠**：Pura X Max 的 `rotate left/right` 不改变 app 窗口尺寸（自然方向为横屏）；用 `devecocli emulator fold close|open --target 127.0.0.1:5555` 才能稳定得到 460vp 竖屏 ↔ 940vp 横屏，验证 `detail_layout` ↔ `detail_landscape` 切换。
30. **M12：UiTest 点列表行要避开表头**：`list_table` 包含 40vp 表头，`bounds.top + 40` 会点到表头触发排序；用 `bounds.top + 120` 落到第二行价格区，且避免点顶部指数条同名文本。

31. **M9：hilog 不支持 `%{public}f`**：写 `%f` 会原样输出 `}f`，JSON 被破坏、脚本解析不到。数值要先 `toFixed()` 拼成字符串，再用 `%{public}s` 输出。
32. **M9：PowerShell 的 `>` 重定向默认不是 UTF-8**：`hdc shell hilog -x > dump.log` 出来的文件 Node 读不到标记行；用 `| Set-Content -Encoding utf8`（`hdc` 输出多行时也更好控）。
33. **M9：缓存预热是异步的**：`EntryAbility.onCreate` 里 `quoteCache().load()` 还没读完，VM 就来查缓存 → 永远 miss。读取路径必须先 `await cache.load()`（同一个 Promise，已读则立即返回）。
34. **M9：列表面板不能连续 `applyData` 两次**：第二次会重建行数组并触发 `FrozenTable` 的旧偏移恢复，真机表现为列表自发跳到第 25 行（4s 内）。缓存优先的正确做法是「repo 命中即返回一次数据」，后续用 `onPatch` 增量刷新。
35. **M9：调试菜单 `showActionMenu` 最多 6 个按钮**：第 7 个加不进去（会静默失败）。M9 把「行情通道」塞进「场景…」二级、把「交易时段/采样与缓存」做成三级，就是为了不超过 6。
36. **M11：详情源只覆盖 50 只主数据**：`MockDetailProvider` 用 `buildStockSeeds()` 建种子，搜索追加种子（如 601398）**没有详情页**，持仓行点进去会 404「该股票不存在或已下架」。样例持仓因此只用主数据代码；AC-120 的「＋」用「把持仓股移出自选」构造（首次 UiTest 用 601398 点行失败即此原因）。
37. **M11：行情 patch 不重排列表**：持仓页排序是快照序，`handlePatch` 只更新数值与仓位、不重新 `sortPositions`，否则每秒都跳序；重排只发生在点 chip 与下拉刷新。
38. **M11：停牌快照 `last`/`prevClose` 都是 null**：不能用 `last ?? prevClose` 估值，必须靠持仓记录上的 `lastPrice`（成交时写入、看到有效行情时更新）；否则停牌股市值直接变 `--`、汇总与逐行对不上（见 §9-51）。
39. **M11：`ui layout` 可能不列某个 chip 的 Text 节点**（「盈亏」chip 在 dump 里缺失但截图可见）：定位点击坐标优先用截图比例或父容器 bounds，别因为 dump 少一行就以为控件没渲染。
40. **点击要落在 `Row` 容器上，点名称 `Text` 不触发行操作（2026-11-14 复测）**：搜索/持仓行内 `Text` 只挂了长按复制，普通点击命中的是 Text 本身；`ui click` 要点行内价格/涨跌幅/右侧空白（`Row` bounds 内、Text 之外）。本轮因此一度误判「板块行点击无效」「指数行无动作」，换到价格区后两者都正常。
41. **本机（`23E0224222002707`）hilog 不输出应用日志**：`hilog -x -P <pid>` 只有系统 `InputKeyFlow` 行，清空后重装重启仍无 app 日志（AppGallery 等系统应用正常）。依赖日志的采样（M8 帧率、M6 索引耗时/埋点、M11 通道）需换设备，或改用界面/单测取证。
42. **设备剪贴板与 PC「协同中」同步**：长按复制后若 PC 剪贴板发生变化，设备粘贴内容会被覆盖（本轮粘出过 `C:\Users\12480`、`8.未完成与阻塞`）。粘贴类验证要在同一流程内完成，不要把 PC 剪贴板内容当证据；`m6/29-copy-menu.png` 保留了「全选 + 复制菜单」这一层证据。
