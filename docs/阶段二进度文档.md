## 10. M6 高频坑（新增）

1. **`ForEach` key 不变会复用旧组件**：搜索段用 `section.kind` 做 key，结果替换后仍显示上一帧（搜 `600519` 显示 67 条「6」的结果）。修法：VM 拍平 `items` + key 带版本号（`SearchSectionVM` / `SearchItemVM`）。
2. **异常态分支必须优先于旧结果**：`SearchBody` 先判 `items.length > 0` 会让 error/429 被旧结果挡住；空/错/限流分支要放在结果分支之前。
3. **LRU 缓存会绕过 debug 故障注入**：同 term 命中缓存直接返回成功；注入前调用 `SearchQuery.clearCache()`。
4. **数字逐字符输入会触发多次查询**：`ui text "600519"` 会依次产生 `6`/`60`/… 的 onChange；首字符即查 + `seq` 丢弃旧响应可保证最终一致，但埋点会多一次 `search_query`。
5. **行点击挂在 `Row` 上，UiTest 点文本不一定命中**：进入详情改为「行内价格区坐标点击」（`getBounds()` + `driver.click(x,y)`）。
6. **`NavDestination` 标题栏不暴露为 Text 节点**：UiTest 断言详情页要用内容（如「今开」），不要用「个股详情」。
7. **长按 `TextInput` 会弹系统文本选择菜单**：搜索调试入口放在搜索条左侧图标区（`Column` 的 gesture），不要指望长按输入框。
8. **hvigor daemon 环境冲突**：`devecocli build` 报 `spawn java ENOENT` / 打包失败，多为此前用另一套 node/hvigor 起过 daemon；先 `hvigorw --stop-daemon` 再 `devecocli build`。
9. **hdc 多目标**：`onDeviceTest` 内部裸调 `hdc`，多设备会报 `need connect-key`；测试期间只保留 1 个目标（停模拟器/拔真机）。
10. **UiTest 前置**：设备必须解锁亮屏；首次 `hdc shell param set persist.ace.testmode.enabled 1`；否则报 `unlock screen failed` / 无 testmode。
11. **`onDeviceTest` 会重装应用并清掉自选数据**：本次跑完 8 例后自选从手工构造的 5 只回到 45 只种子（`watchlist_v1`/迁移标记被清）。需要保留设备上的自选状态时，先跑测试再手工验证；反之可把「清数据后 45 只」当作确定初态。
12. **截图坐标要按真机像素取**：`ui screenshot` 预览是缩放图，点按坐标必须用 `ui layout` 的节点 bounds（本次按预览图估算连点空处，误触发了搜索页与调试菜单）。
13. **自选调试「清空自选（空态）」现在是真删数据**：会清 `watchlist_v1` 的 items 并立即落盘，重启仍空；验证完用「重置」恢复 45 只种子（也会落盘），不要拿它当"看一眼空态"的临时开关。
11. **preferences 必须注入 context**：HAR 内不能自己拿 AbilityContext；由 `EntryAbility` 注入。
12. **`.hvigor` 目录权限**：本工作区曾因 Windows ACL 缺 `WRITE_OWNER` 导致 `mkdir .hvigor/.build-lock` EPERM；用权限诊断脚本修复后正常（报告在 `acl-report/`）。
