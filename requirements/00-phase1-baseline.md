### 4.1 占位文案规范（DEC-10-02）

**唯一模板**：`{对象}下阶段开放`

| 对象 | 触发 | 呈现 | 文案 |
|---|---|---|---|
| 添加自选 | 点底部胶囊按钮 | toast | 添加自选下阶段开放 |
| 卡片视图 | 点视图切换图标 | toast（图标保持可点、不置灰） | 卡片视图下阶段开放 |
| 首页 | 切到首页 Tab | 整页空态 | 标题「首页」+ 说明「首页下阶段开放」 |
| 最新资讯 | 切到资讯 Tab | 整页空态 | 标题「最新资讯」+ 说明「最新资讯下阶段开放」 |
| 行情 | 切到行情 Tab | 整页空态 | 标题「行情」+ 说明「行情下阶段开放」 |
| 搜索 | — | **不出现**（设计稿无入口，不新增） | — |

**硬性规则**：

1. 只用「下阶段开放」收尾，禁止「敬请期待 / 即将上线 / 暂未开放 / Coming Soon」等任何变体。
2. 不加标点、感叹号、emoji；不加版本号（不写「下阶段（v1.1）开放」）。
3. 对象名取**界面原词**，不另造词（不写「自选添加」「卡片模式」）。
4. 文案集中在**一份常量表**，`ComingSoon` 组件只引用；禁止在页面里硬编码字符串。
5. 呈现两种，不混用：点击类入口用 toast（1.8s、居中偏下）；页面类用常驻空态。
6. 空态页除标题与说明外不放置第二个操作按钮，避免出现「点进去又是占位」。
7. 空态页不新增插画资源，用统一的灰色图标位。
8. 读屏：toast 需播报文案；空态说明可被朗读。
9. 中文文案走 i18n 资源，不写进布局代码。

**反面示例**（评审时直接判不合格）：`该功能暂未开放，敬请期待`、`Coming soon...`、`卡片视图开发中~`。

## 6. 断点与布局口径

| 断点 | 宽度 | 列表形态 | 详情形态 | 11 列 1.0× 横滑量 |
|---|---|---|---|---|
| sm | <600（375） | 单列 | 全屏页 | ≈491vp |
| md | 600–840（720） | 单列 | 全屏页 | ≈146vp |
| lg | 840–1200（1000） | 单列 | 可全屏 | 0 |
| xl | >1200（1180） | 左栏 ≈523 | 右栏嵌入 | ≈311vp |

**口径修正**：`CC-6.3 / AC-13` 的「1.3× 在 ≥1180 不横滑」**仅适用于整宽列表**；分栏形态下列表宽度约 523vp，11 列必然横滑，该条不适用。分栏下改考核三项：名称列冻结、表头与数据列对齐、右栏选中联动不丢横滑偏移。

## 7. 数据契约与 Mock

| 接口 | 职责 | Mock 必须支持 |
|---|---|---|
| `QuoteProvider` | 快照 / 推送 / 盘口 / 分笔 | 1s 推送、增量 patch、断线、延迟、429 |
| `AccountService` | 登录态 / 股东账户 / 可买 / 持仓 | 未登录、未开户、可买 0、单账户 |
| `TradeGateway` | 委托受理 | 成功 / 失败（资金不足、超涨跌停、风控）/ 超时 / 幂等去重 |

实体：`QuoteSnapshot`、`WatchItem`、`Group`、`OrderDraft`、`OrderResult`（字段见 `fr06-subreq.md` §3、`fr07-subreq.md` §3、`fr08-subreq.md` §3）。

Mock 数据集下限 **12 只**，覆盖 涨 / 跌 / 平 / 停牌 / 新股 / 负市盈率 / 涨停 / 跌停。

调试面板（仅 debug 构建）：切断线、切延迟、注入失败、模拟内存告急、模拟 3 窗。

## 12. 技术基线（API 20）

| 项 | 取值 | 说明 |
|---|---|---|
| `compileSdkVersion` | **20** | — |
| `targetSdkVersion` | **20** | — |
| `compatibleSdkVersion` | **20**（DEC-10-03） | 仅覆盖 HarmonyOS 6.x；5.x 设备不支持 |
| `runtimeOS` | HarmonyOS | — |
| 语言 | ArkTS | 严格模式 |
| 状态管理 | ArkUI 状态管理 **V2** | API 20 下 V2 为推荐路径，V1 不再作备选 |
| 构建 | DevEco Studio（与 SDK 20 匹配）+ hvigor | 具体版本以本地安装为准 |
| 包管理 | ohpm | — |

### 12.1 开工前必须核验（4 项，缺一不可）

| # | 核验 | 不通过的后果 | 处理 |
|---|---|---|---|
| 1 | 本地已装 API 20 SDK，IDE / hvigor / SDK 三者版本一致 | 编译不过 | 先升级工具链 |
| 2 | 折叠屏真机 API 版本 ≥ 20 | 装不上包，M4 与折叠验收全部阻塞 | **已确认：真机已升级至 API 20** |
| 3 | 三方图表库（`@ohos/mpchart`）在 API 20 下可编译、可跑 | 详情与多窗的核心组件缺位 | 换库或退 Canvas 自绘（+3~5 人日） |
| 4 | V2 装饰器与 `Navigation` 在 API 20 的行为符合预期 | 状态管理返工 | V0 先写最小样例验证 |

### 12.2 兼容规则

- min 已定为 **20**：20 以内的能力可直接使用，无需 `canIUse`。
- 未来若提高 `compileSdkVersion` 而不提高 min，新增能力必须 `canIUse` 判断。
- 三方库若只发布到较低 API，需确认在 20 下编译通过，并在 V0 记录其已验证的最高 API。
- 每次升级 SDK 小版本，回归三处最易受影响的功能：**11 列横滑、多窗、图表**。

### 12.3 对既有选型的影响

| 既有结论 | 在 API 20 下 |
|---|---|
| 状态管理 V2 | 不变，且不再保留 V1 备选 |
| 多窗宿主抽象 `WindowHost` | 不变；若 20 有更合适的窗口编排 API，只在实现层替换 |
| 图表选型 | 不变，但兼容性从「待验证」升级为「开工前必验」 |
| 最小 API | 定为 **20**（DEC-10-03），不再保留 5.x 兼容分支 |
