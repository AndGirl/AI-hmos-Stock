## 1. 术语

| 术语 | 定义 |
|---|---|
| 系统组（system group） | 由股票板块标签自动继承的组：融→融资融券、创/科→创业板。不可增删、不可改名 |
| 用户组（user group） | 用户自建分组，可增删改名，最多 7 个 |
| 「全部」 | 虚拟组，成员为所有组并集，不可增删 |
| SortState | 全局唯一的排序状态对象 |
| SearchService | 全局唯一的搜索实现，由 FR-05 提供 |
| ConnectionState | 全局唯一的行情连接状态 |
| fontScale | 系统字体缩放系数 |
| 摘要视图 | 卡片视图的定位：只展示核心指标，不追求与列表等价 |

## 2. CC-1 规模与容量

**CC-1.1 上限** 自选上限 **50 只/账号**（D3）。分组不设独立上限，均受账号上限约束。

**CC-1.2 性能基线按 50 计**
- 首屏骨架 ≤300ms、首屏内容 ≤1s
- 50 行 / 50 卡连续滚动 ≥55fps，无白块
- 单行推送只更新对应行（不整表重绘）

**CC-1.3 压测口径**
200 行 / 200 卡**超出产品规模**，仅用于容量评估：记录帧率与首屏耗时，**不设通过阈值、不计入验收**，用例优先级 P2。

**CC-1.4 回滚条件**
若 D18 改判为「50 为单分组上限」，则 CC-1.2 的规模基线改为 `50 × 分组数`，CC-1.3 的压测口径同步上移（200 恢复为可达规模）。

**CC-1.5 受影响条款**
FR-02：AC-02、TC-007、TC-014、TC-015、TC-015b；FR-03：AC-21、TC-035 ~ TC-037b。

## 3. CC-2 分组模型

**CC-2.1 组类型**

| 类型 | 来源 | 可增删 | 可改名 | 数量 |
|---|---|---|---|---|
| system | 由板块标签自动继承（融→fin，创/科→star） | ✗ | ✗ | 固定 2 个 |
| user | 用户创建 | ✓ | ✓ | ≤7 |
| virtual | 「全部」 | ✗ | ✗ | 1 个 |

**CC-2.2 多归属**
一只股票 = **至少 1 个系统组 + 0..n 个用户组**。加入自选时，系统组按标签自动继承，用户组按用户选择叠加；多组同时归属不产生重复行。

**CC-2.3 「全部」语义**
虚拟组，成员为所有组并集，**自动去重**；排序、筛选、搜索不改变其成员集合。

**CC-2.4 命名解耦**
`groupId` 与 `displayName` 必须解耦，**禁止用展示名做分支判断**。
> 现存遗留：组 id `star` 的展示名是「创业板」，语义错位。冻结期内不改，但**新代码禁止再引入此类错名 id**；迁移时以 `gem` 取代 `star`，且 `star` 不可被复用。

**CC-2.5 删除语义**
删除用户组只删归属，不删股票；删除后所有股票仍须满足 CC-2.2，**不允许出现无组股票**。

**CC-2.6 指数条绑定**
指数条按 `IndexSet[groupId]` 配置，切组时整组替换（含项数、顺序）；无配置的组隐藏指数条并收缩高度，不留空白占位。排序不影响指数条。

**CC-2.7 数据形态**

| 对象 | 字段 |
|---|---|
| Group | `id`、`name`、`type`(system/user/virtual)、`order` |
| WatchItem | `code`、`groups[]`、`addedAt`、`pending`(离线待同步) |
| IndexSet | `groupId`、`indexes[]`(`code`、`name`) |

**CC-2.8 不变量**

| 编号 | 约束 |
|---|---|
| INV-1 | 每只股票至少属于 1 个系统组 |
| INV-2 | 「全部」成员 = 所有组并集且无重复 |
| INV-3 | 删除用户组后，INV-1 仍成立 |
| INV-4 | `groupId` 全局唯一，删除后不可复用 |
| INV-5 | 同一股票在同一组内至多出现一次 |

**CC-2.9 字段拆分（D24）**
`tags[]` 只承载**板块与状态标记**（融 / 创 / 科 / 停 / 新）；`groups[]` 只承载**分组归属**（系统组 + 用户组 id）。
- 禁止再用 `tags.includes('fin')` 之类的方式判断分组。
- 派生只发生在**加入自选的瞬间**：`groups = deriveGroups(tags) ∪ 用户选择`；此后 `groups` 独立存储、独立增删。
- 搜索结果的"是否已添加"读自选仓储，不读 tags。

## 4. CC-3 搜索服务

**CC-3.1 归属** 搜索能力**唯一实现在 FR-05**（SearchService）；FR-04 添加页、FR-06 详情页只允许调用，不得自带匹配、防抖或离线规则。

**CC-3.2 契约**

```
query(term, { limit, scope }) → {
  term, seq, took,
  buckets: [{ type: 'stock' | 'index' | 'board', items: SearchItem[] }],
  source: 'remote' | 'cache' | 'offline',
  partial: boolean
}
SearchItem = { code, name, market, tags[], price, pct, added }
```

**CC-3.3 匹配层级** L0 代码精确 → L1 代码前缀 → L2 名称前缀 → L3 名称包含 → L4 拼音全拼 → L5 首字母 → L6 板块标签；同层按成交额降序。

**CC-3.4 防抖与竞态** 300ms 防抖；按 Enter 跳过防抖；每次请求自增 `seq`，响应 `seq` 不匹配即丢弃并取消在途请求。

**CC-3.5 缓存与离线** LRU 缓存 5min（key 为归一化 term）；离线时仅查本机证券主数据，`source='offline'`、`partial=true`，UI 必须展示来源提示。

**CC-3.6 分页** 每个 bucket 默认返回 20 条，超出需显式展开。

**CC-3.7 消费方约束** FR-04 若需要不同结果形态，只能通过 `scope`/`limit` 参数表达，**不得复制匹配逻辑**。

## 5. CC-4 排序状态

**CC-4.1 定义**

```
SortState = { key: 'price'|'chg'|'pct'|'vol'|'amt'|'amp'|'turn'|'pe'|'pb'|null,
              dir: 'desc'|'asc'|'none' }
```

**CC-4.2 两入口写同一状态** 列表列头点击与卡片「三横线」排序面板**共用同一个 SortState**；列头循环 `desc → asc → none`。

**CC-4.3 生命周期** 切换视图保留排序；切换分组保留排序；清空/新增自选保留排序；退出应用不持久化（默认手动序）。

**CC-4.4 空值处理** 停牌、新股等空值**恒定排在末尾**，不随升降序翻转。

**CC-4.5 指数条随列表（2026-11-12 调整）** 指数条与列表行逐股票一一对应，排序会同步改变指数条的条目顺序；排序不影响指数条条目的数值来源（仍为同一行情快照）。

## 6. CC-5 摘要视图

**CC-5.1 信息集** 卡片 = 名称 + 代码 + 标签 + 最新价 + 涨跌/涨跌幅 + **6 项指标**（今开、最高、换手、市盈率、振幅、市净率）。

**CC-5.2 不等价声明** 卡片是**摘要视图**，不承诺与列表的 11 列信息等价；切换视图时不做"信息补全"提示，也不在卡片内追加载荷字段。

**CC-5.3 朗读口径** 卡片朗读覆盖上述全部字段，**不朗读未展示列**（如总量、现量、成交额）。

**CC-5.4 卡片视图的交互（C11）**
- **保留分组 Tab**，与列表共用同一 `group` 状态，切换视图不重置。
- 排序走列表同款「三横线」面板；选好后在分组栏下方出现**可清除的排序 chip**，与列表共用 `SortState`。
- 卡片视图不另设排序入口，避免出现第三套排序态。

## 7. CC-6 字体与尺寸缩放

**CC-6.1 缩放系数** `fontScale ∈ {1.0, 1.3, 1.45}`，跟随系统字体设置。

**CC-6.2 列宽公式** `列宽 = round(base × fontScale)`，名称列 `minmax(baseName × fontScale, 1fr)`。
基准（base）**只能取 CC-6.3 表内数值，不得各页自定**；当前实现存在 870 / 834 / 784 三套基准，须统一为 834。

**CC-6.3 基准列宽（base，vp）**

| 名称 | 最新价 | 涨跌 | 涨跌幅 | 总量 | 现量 | 成交额 | 振幅 | 换手 | 市盈率 | 市净率 |
|---|---|---|---|---|---|---|---|---|---|---|
| 112（弹性） | 76 | 70 | 78 | 82 | 68 | 78 | 66 | 66 | 70 | 68 |

1.3× 时总宽 1084vp，**在 ≥1180vp 屏仍不横滑**；1.45× 时总宽 1209vp，**允许横滑**（AC-13 口径以本表为准）。横滑距离变长属预期，**不做列合并、截断或隐藏**。

**CC-6.4 冻结配合** 放大后仍须保持表头竖向冻结与名称列横向冻结；横向滚动条与右侧渐隐保留。

**CC-6.5 禁止做法** 不得用缩小字号、省略号截断、隐藏列来"适配"放大字体；不得因放大而改变列顺序。

## 8. CC-7 连接状态机

**CC-7.1 状态**

| 状态 | 含义 |
|---|---|
| `online` | 行情正常推送 |
| `weak` | 网络较弱，推送间隔变长 |
| `offline` | 连接中断，无推送 |
| `delayed` | 数据延迟，仍有推送 |

**CC-7.2 迁移**

| 事件 | 目标状态 |
|---|---|
| 连续 2 次心跳超时 | weak |
| 断网 / 心跳失败 ≥3 次 | offline |
| 服务端标记延迟 | delayed |
| 重连成功 | online（5s 内提示消失并刷新） |

**CC-7.3 提示条契约** 全局**单例** banner，位于页面列表区顶部；同一时刻最多显示 1 条，禁止各页各自叠加；文案由状态决定，不由页面决定。

**CC-7.4 文案**

| 状态 | 文案 |
|---|---|
| weak | 网络较弱，行情更新较慢 |
| offline | 行情连接中断，数据可能延迟 |
| delayed | 延迟（角标形式，附在涨跌幅列头） |
| online | 不展示 |

**CC-7.5 重试退避** 1s → 2s → 4s → 8s → 16s → 30s 封顶；恢复后回到 1s。**重连由单一调度器负责，页面不得自带定时器。**

**CC-7.6 断线时的数据处置（C10，全局规则）**
连接为 `offline` 时，所有页面执行同一套动作，不允许各页自定：

| 动作 | 规则 |
|---|---|
| 数据 | **冻结**为断线前最后一帧，不清空、不切骨架 |
| 视觉 | 列表/卡片整体**置灰**（约 55% 透明度），表头与名称列仍保持可读 |
| 提示 | 顶部**唯一** banner「行情连接中断，数据可能延迟」 |
| 时间 | **不在行内**显示"最后更新时间"，避免把延迟误读为个股信息 |
| 恢复 | 回到 `online` 后 5s 内 banner 消失、去灰并刷新数据 |

`weak` / `delayed` 不置灰，只保留 banner 与角标；页面不得自带重连计时器。
