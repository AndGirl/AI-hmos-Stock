# 阶段二需求基线（Phase-2 Baseline）

> 版本：v0.1 · 编制：2026-11-11 · 状态：**草案，待评审**
> 前提：阶段一（`00-phase1-baseline.md`）M0–M5 已交付并通过验收
> 输入：阶段一基线 + 阶段一遗留占位 + 待补设计稿 + 真实数据源/交易通道
> 效力：阶段二只做**增量**，不推翻 FR-06/07/08 的结构；与阶段一基线冲突时以本文件为准。
>
> **本版定位**：把应用从「可演示」推到「可上线」。三个模块（搜索 / 添加自选 / 卡片视图）在阶段一只留了入口，阶段二必须补齐；行情与交易要从 Mock 换成真实通道。最大风险不在技术，而在**数据授权与交易资质**。

---

## 0. 与阶段一的关系

| 阶段一交付 | 阶段二动作 |
|---|---|
| 三个占位入口（添加自选 / 卡片视图 / 无搜索入口） | 落地为完整功能（M6 / M7 / M8） |
| `QuoteProvider` / `AccountService` / `TradeGateway` 三个 Mock | 换真实实现，**契约不变**（M9 / M10） |
| 单账户、无持仓、无委托列表 | 补持仓与委托（M10 / M11） |
| 不做深色、不做横屏 | 按需补（M12） |
| 未上架 | 合规与上架（M13） |

**前置条件**：阶段一的三个 Provider 契约必须已冻结并有真实实现的占位类；否则 M9/M10 会退化成重写。
**技术基线**：继承阶段一 §12——`compileSdkVersion` / `targetSdkVersion` = **API 20**，状态管理 V2；阶段二新增能力若仅高版本可用，按 §12.2 的兼容规则处理。

## 4. 需求条目

### M6 搜索（AC-87 ~ AC-93）

| 编号 | 条目 | 规则 | AC |
|---|---|---|---|
| M6.1 | 入口与形态 | 行情 Tab 搜索框 + 自选空态 + 深链；sm/md 全屏，lg/xl 左结果右预览 | AC-87 |
| M6.2 | 输入与防抖 | 首字符即查、300ms 防抖、Enter 跳过、`seq` 丢弃旧响应 | AC-87 |
| M6.3 | 匹配层级 | L0 代码精确 → L6 板块，六层；同层按成交额降序 | AC-88 |
| M6.4 | 结果与高亮 | 股票/指数/板块三段；命中片段高亮，不破坏复制与读屏 | AC-89 |
| M6.5 | 历史与热搜 | 本地历史 ≤10 条、可单删可清空；热搜失败整块隐藏 | AC-90 |
| M6.6 | 结果操作 | 点击进详情（带 from/rank）；行尾「＋」就地加自选 | AC-91 |
| M6.7 | 异常 | 无结果/失败/离线/429 四态，均可重试 | AC-92 |
| M6.8 | 性能 | 输入到结果 ≤500ms（P90）、缓存 5min | AC-93 |

### M7 添加自选与分组（AC-94 ~ AC-99）

| 编号 | 条目 | 规则 | AC |
|---|---|---|---|
| M7.1 | 入口 | 底部按钮、空态按钮、卡片虚线卡、详情「自选设置」 | AC-94 |
| M7.2 | 添加页容器 | sm/md 全屏 push；lg/xl 居中模态；进入即聚焦 | AC-94 |
| M7.3 | 多选与提交 | 批量多选、底部计数、目标分组默认当前 Tab、可多选叠加 | AC-95 |
| M7.4 | 重复与容量 | 已在自选不重复；账号上限 50；批量部分超限时成功项生效 | AC-96 |
| M7.5 | 插入与撤销 | 乐观插入；无排序追加末尾并高亮；有排序按序落位；移出 5s 可撤销 | AC-97 |
| M7.6 | 编辑模式 | 多选移出、二次确认、全选/取消 | AC-98 |
| M7.7 | 分组管理 | 新建/重命名/删除（≤7）；系统组不可改；删除只删归属 | AC-99 |

## 5. 验收策略

| 维度 | 做法 |
|---|---|
| 设备 | 延续阶段一矩阵；M10 需真机 + 真实账户（或沙箱账户） |
| 网络 | 弱网/断网/限流三档必须真机测，Mock 不算 |
| 数据 | 真实行情需与源端抽样比对（价格、时间、涨跌停一致率） |
| 合规 | 隐私弹窗、权限申请时机、SDK 清单逐项走查 |
| 回归 | 阶段一 AC-01~86 全量回归，不允许因二期改动退化 |
