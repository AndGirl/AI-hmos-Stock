# FR-08 多窗 / 比价 · 子需求条目表

> 版本：v1.0 · 编制：2026-11-11 · 状态：**待评审**
> 效力：受 `fr-common-spec.md`（CC-5 / CC-6 / CC-7）约束；详情内容与紧凑版由 FR-06 提供，自选多选与搜索换股分别由 FR-02 / FR-05 提供，本 FR **只做编排**。
> 范围：PK 组建立、窗口宿主、数量与布局、标的绑定与换股、创建/聚焦/关闭、跨窗一致与同步、订阅预算、生命周期与恢复、异常降级、多端、无障碍、埋点。
> 验收：本 FR 原无 AC，**建议新增 AC-77 ~ AC-86**（编号待与 PRD 主文档对账，见 §7）。
> 设计依据：`design/折叠屏分屏-双股比价.png`、`design/折叠屏全景多窗-三股比价.png`。
> 验证件：`validation/fr08-multiwindow-validation.html`（20 条自动用例，**不计入需求文档**）。
>
> **本版要点**
> - **D43–D48 全部按建议默认定案**：宿主抽象、上限 3 窗、禁止同标的重复、周期默认不同步、组合持久化 1 组、三入口。
> - 拆分写成**宿主无关**：`WindowHost` 抽象同时容纳「应用内窗格」与「系统多实例」，两种实现共用同一组验收。
> - 每窗独立持有 `code` / 周期 / 订阅（INV-D3），编排层不得共享可变状态。

## 0. 拆分方法（为什么切成这 12 条）

FR-08 在既有文档里只有一句「窗口创建、布局、同步」（`fr06-subreq.md:180`），设计稿只给了「两窗并排」与「三窗叠放」两张全景图。本次沿四条正交线拆分：

| 拆分线 | 落点 | 对应条目 |
|---|---|---|
| 用户任务链 | 发起 PK → 组窗 → 看清对比 → 换标的 → 退出 | 08.1 → 08.3/08.4 → 08.6 → 08.5 |
| 窗口生命周期 | 创建 → 绑定 → 订阅 → 可见 → 降频 → 销毁 → 恢复 | 08.2、08.5、08.7、08.8 |
| 跨窗一致性 | 哪些必须一致、哪些可选、哪些禁止 | 08.6 |
| 质量属性 | 订阅预算、异常降级、多端、无障碍、埋点 | 08.9 ~ 08.12 |

**不拆的方向**（明确排除，避免条目膨胀）：行情推送协议、图表绘制与盘口（FR-06.7/06.8）、窗口系统本身（系统能力）、自选与搜索本体（FR-02/05）、买入委托（FR-07）。

## 2. 关键规则（表内写不下的部分）

### 2.1 窗口宿主（D43 的落地）

`WindowHost` 只约束三件事：**持有实例、给出尺寸、提供可见性**；页面内容不感知宿主类型。

```
WindowHost
  ├─ PaneHost    应用内窗格：一个 page 内并排 N 个 DetailContent
  └─ WindowHost  系统多实例：N 个 window，各跑一套 page
```

| 编号 | 约束 |
|---|---|
| INV-W1 | 每个宿主实例独立持有 `code`、周期、缩放与订阅（沿用 INV-D3） |
| INV-W2 | 任一时刻只有一个实例持有焦点，且高亮可见 |
| INV-W3 | 同一 `code` 允许出现在多个实例，但订阅必须合并为一路 + 多播 |
| INV-W4 | 关闭实例必须同步释放其订阅、定时器与图表对象，不得残留 |
| INV-W5 | 编排层（PK 组）不得持有页面内容引用，只持有 `code` 与布局参数 |

| 维度 | 方案 A：应用内窗格 | 方案 B：系统多实例 |
|---|---|---|
| 状态共享 | 天然共享 ViewModel | 需跨窗服务 + 持久化 |
| 与稿的贴合 | 贴合「分屏双股」 | 贴合「全景多窗」 |
| 风险 | 三窗同页的性能与内存集中 | 冷启恢复、窗口数限制、跨窗通信 |
| 本期取舍 | **先落 A**，保留 B 的接入位 | 二期接入，验收口径不变 |

### 2.2 布局规格

| 窗数 | 布局 | 中缝 / 重叠 | 圆角 | 指示器 |
|---|---|---|---|---|
| 1 | 单窗铺满 | — | 14vp | 无 |
| 2 | 左右 1:1 | 中缝 8vp | 14vp | 无 |
| 3 | 卡片叠放 | 相邻重叠 **12vp**，焦点窗置顶 | 16vp | 顶部 3 点，可点可滑，当前点高亮 |

窗宽计算：n=2 时 `(W - 8) / 2`；n=3 时 `W / 3 + 6`（配合 -12vp 外边距形成重叠，三窗整体仍在容器内，关闭按钮不被裁切）；`cardW < 360vp` 即切换紧凑版（隐藏盘口、内容 Tab 与动作栏，动作收进「⋯」）。

### 2.3 跨窗同步分级

| 级别 | 项 | 理由 |
|---|---|---|
| 必须一致 | 配色、空值、时间轴刻度、交易状态、断线视觉 | 否则「比价」结论被视觉差异污染 |
| 可选同步 | 周期（一次性按钮，作用于全部窗） | 比同周期是高频需求，但强同步会顶掉用户手动切过的窗 |
| 禁止同步 | 滚动、内容 Tab、缩放、十字光标 | 各窗是独立观察视角，同步反而破坏对比 |

### 2.4 订阅、降频与性能预算

| 项 | 预算 |
|---|---|
| 订阅数 | 3 窗 ≤ 3 路逻辑订阅；同 `code` 合并后更少 |
| 降频 | 非焦点窗 1s → 5s；恢复焦点后立即补全量，首帧 ≤300ms |
| 帧率 | 3 窗同屏 ≥50fps，滚动无白块 |
| 内存 | 关闭全部窗后订阅数归零，内存回到单窗基线 ±5% |
| 冷启恢复 | 杀进程后 ≤800ms 恢复到上次组合 |

### 2.5 状态与降级矩阵

| 状态 | 表现 | 处置 |
|---|---|---|
| 正常 | 各窗实时、焦点窗 1s、非焦点 5s | — |
| 单窗数据失败 | 该窗局部错误 + 重试，其它窗正常 | 不整页报错、不全局置灰 |
| 断线 `offline` | 全部窗冻结 + 置灰 55% + 页面级**唯一** banner | 复用 CC-7.6，窗内不各自叠加 |
| 内存不足 | 按「关非焦点窗 → 降频 → 退单窗」顺序降级 | 每次降级给出一次 toast 说明 |
| 超上限（第 4 窗） | 「+」禁用，点击提示「最多 3 只对比」 | 不新建、不挤掉已有窗 |
| 恢复失败 | 降级为单窗并提示 | 保留最后 1 组快照供重试 |

### 2.6 生命周期时序

```
进入 PK ── 建组 ── 开窗(1..n) ── 绑定 code ── 订阅(合并) ── 可见(1s)/非焦点(5s)
                                                           │
  退出 PK ◀── 关闭窗(逐个退订) ◀── 恢复/降级 ◀── 焦点切换 ──┘
```

约束：每个阶段失败都要**停在可操作状态**（例如订阅失败仍可看上一帧），不得出现空白窗。

### 2.7 埋点

| 事件 | 触发 | 字段 |
|---|---|---|
| `pk_entry` | 三入口之一 | 入口类型、来源页 |
| `group_created` | PK 组建立 | 组大小、是否被截断 |
| `window_open` / `window_close` | 开窗 / 关窗 | 窗序、当前窗数 |
| `code_swap` | 换股（尤其交换） | 源窗、目标窗 |
| `period_sync` | 同步周期 | 目标周期、窗数 |
| `degrade` | 降级 | 原因（内存 / 上限 / 失败） |
| `exit_pk` | 退出 | 停留时长、窗数 |

## 3. 数据契约（建议）

```ts
PkGroup = {
  id: string,
  codes: string[],            // 有序，长度 2..3，去重
  createdAt: number
}

WindowState = {
  code: string,
  period: 'timeline' | 'five' | 'd' | 'w' | 'm' | 'q' | 'hy' | 'y',
  zoom: number,               // 图表缩放，独立
  subscribed: boolean,
  failed: boolean
}

PkSession = {
  group: PkGroup,
  host: 'pane' | 'window',
  windows: WindowState[],     // 1..3，顺序即窗序
  focus: number,              // 焦点窗下标
  layout: 'single' | 'split' | 'deck'
}
```

- 每个 `WindowState` 由宿主实例持有；`PkSession` 只保存 `code` 与布局参数（INV-W5）。
- 组合持久化只存最后 1 组：`{ codes, periods, focus }`，不存行情数据。

## 5. 设计稿疑点（已按默认处理，标注需补图项）

| 编号 | 现象 | 处理结论 | 是否阻塞 |
|---|---|---|---|
| Q1 | 两张稿所有窗的标的完全相同（都是 `60**19`），连价格都一致 | 视为 Mock 复制；**禁止同标的重复**（DEC-08-03），换到已占用标的走**交换** | 否 |
| Q2 | 双窗稿两窗都保留完整内容 Tab 与动作栏，垂直空间明显不足（内容被裁） | 按窗宽自动紧凑化（<360vp），不按窗数硬编码 | 否 |
| Q3 | 三窗稿第 3 窗只露约 55vp 边缘，无关闭/切换控件 | 定为「叠放 + 顶部指示器」，点指示器或滑动手势切换焦点 | **需设计补图**（手势与指示器交互） |
| Q4 | 顶部三个圆点：窗数指示还是页面指示 | 定为**窗数指示**，可点、可滑，当前点高亮，可朗读「第 2 个，共 3 个」 | 否 |
| Q5 | 右上 ⧉ 图标语义未定义（两张稿都有） | 定为「进入/退出 PK」入口，不承担布局切换 | 否 |
| Q6 | 双窗之间无可见分隔 | 定为 8vp 中缝（露出浅灰底，不额外画线） | 否 |
| Q7 | 稿内数值不自洽（`20.01 +19.8 +0.64%`） | 同 FR-06 Q2 / FR-07 Q2：占位，不作验收基准 | 否 |
| Q8 | 每窗都有「去交易」与完整动作栏 | 保留每窗入口，但全局同时只允许一个弹窗实例 | 否 |
